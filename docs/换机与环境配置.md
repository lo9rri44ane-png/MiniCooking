# 换机与环境配置

## 最短路径

1. 安装Git、Node.js22+、Creator3.8.8。需要AI协作时安装Codex及Python3.10+。
2. git clone仓库，在仓库根目录执行 `npm run setup`。它安装根工程与MCP扩展的锁定依赖并编译扩展，失败会显示原始错误，可修复网络后重复执行。
3. Dashboard添加克隆目录，固定3.8.8打开，等待首次导入，预览 `assets/scene/main.scene`。
4. Codex打开同一目录。`.agents/skills`与`_bmad`随仓库提供，不需要原电脑上的全局技能目录。

Git只同步源文件，不同步这台电脑上的体力/通关进度。不同电脑的本地存档独立，尚无云存档功能。

## Cocos与Codex连接

- 工程内扩展位于 `extensions/cocos-mcp-server`；setup会生成其dist与依赖。若Creator已提前打开，完成setup后在扩展管理器刷新/启用，必要时重启当前编辑器。
- 在Creator扩展菜单打开Cocos MCP Server面板，把HTTP端口设为 **31388** 并启动。
- `.codex/config.toml` 已声明 `http://127.0.0.1:31388/mcp`；按Codex界面提示信任本地工程配置并重新加载MCP连接。
- 先查询project_get_project_info，核对返回目录与当前克隆目录一致，再让Agent编辑。工具的路径校验随当前仓库位置解析，没有固定E盘依赖。
- 同一端口只连接一个工程。这个接口控制的是本地编辑器，不需要OpenAI API Key；Codex自身的账号与额度由使用者自己的登录提供。
- 项目内作者工具使用当前扩展的组件UUID，相关.meta已保留。日常不要运行generate-prefabs脚本，它会覆盖占位布局；美术修改直接保存预制体。

## 类型检查

先让Creator3.8.8完成工程导入，再执行 `npm run typecheck`。工具优先使用该工程的 `temp/declarations/cc.d.ts`。

如果未生成声明，可指定安装路径：

```powershell
$env:COCOS_CREATOR_PATH = '你电脑上的Creator3.8.8目录/CocosCreator.exe'
npm run typecheck
```

macOS可指定Creator.app目录。也可在仓库根目录创建被Git忽略的 `config.local.json`：

```json
{"cocosCreatorPath":"D:/你自己的目录/CocosCreator.exe"}
```

工具会核实指定引擎版本。不会下载引擎或用模拟声明冒充检查成功。

## 自动化预览（可选）

正常试玩只需Creator预览，不需要安装浏览器测试组件。自动化测试时执行 `npm run setup:browser` 下载Chromium，先启动Creator的Web预览（默认7456），再执行 `npm run verify:ui` 或 `npm run verify:tutorial`。

Windows已有Edge时可以跳过浏览器下载：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run verify:ui
```

部分历史预览脚本只适用于当时的原型阶段，当前基线以verify:ui与verify:tutorial为准。

## 常见问题

| 现象 | 处理 |
|---|---|
| npm命令不存在 | 安装Node.js22+后重新打开终端 |
| npm ci失败 | 检查npm网络/代理与Node版本，重试setup；不要删除锁文件随意升级依赖 |
| 打开工程缺资源 | 等待Creator导入完成；确认assets和同名.meta都拉取完整；确认打开的是仓库根目录 |
| TS声明找不到 | 用3.8.8打开一次；或指定COCOS_CREATOR_PATH |
| MCP连接不上 | setup完成后启用扩展、启动31388服务；检查端口占用与Codex工程信任 |
| MCP返回另一个工程 | 停止错误工程服务，在目标工程启动；路径核对未通过不执行编辑 |
| 提示广告未接入 | 当前预览的预期行为，GM扩展格仅供调试，不代表真实奖励广告成功 |
| Git拉取冲突 | 先提交本机改动再pull；scene/prefab/meta冲突需在Creator验证，不能随机改UUID |
| 字体/音频效果不同 | 当前用系统字体且没有默认音频；正式素材仍待制作 |

## 两台电脑协作

每次开始先 `git pull --ff-only`；修改后验证并 `git add -A`、`git commit`、`git push`。更换电脑前先推送。不要同步library/temp/node_modules，不要上传API Key、平台证书或本地用户存档。设计文档、关卡与资源.meta跟源码一起提交。

历史文档可能保留最初的E盘地址或原验证机路径，仅用于追溯；当前README、运行入口和换机说明以相对路径为准。引擎发布、真实广告、账号登录、支付与真机适配未因上传仓库而自动完成。
