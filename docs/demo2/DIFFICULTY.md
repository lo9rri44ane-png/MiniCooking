# Demo2 难度构造与审计

本轮难度目标是必须腾挪空位，不能把逆向打乱产生的冗长存储解当作难度证明。当前操作仍允许自动寻找转弯通路；没有改成直线滑块。

## 指标
- 初始占用率：所有餐盒与食物覆盖格子的并集除棋盘总格数，已装盒食物不重复计格。
- 锁区：另列不可用格数；不能把锁区当成普通空位。
- 零腾挪组装出餐捷径：使用真实Demo2Customers按食物数量分配首批需求，枚举同类同形食品实例、餐盒及两种装入顺序；用shipping actDrag检查不预先挪动任何盒子的直接组装出餐。单食物2动作、双食物3动作同样算捷径，不拿组合自然多一步冒称更难。
- 腾挪证明：新障碍导致原动作无法执行时，保存由实际规则验证的空位搬移序列，再继续后续装盒出餐。
- 可行解长度不是最优解；当前未穷尽所有完整局面，因此不将动作数直接标为“最少”或“难度分”。

## 作者命令
原工具 tools/demo2-generate-levels.mjs 是稀疏逆向构造底稿。默认拒绝覆盖手工/密集化数据；只有明确要重建底稿才加 --regenerate-sparse-base，之后必须重做密集化和全部实际规则回放。

有效作者工具：`tools/demo2-densify-chains.mjs --apply` 尝试有界搜索搬移链；`tools/demo2-block-shortcuts.mjs --apply` 尝试合法重排减少直通出餐。二者默认拒绝修改关卡，写入后必须重新验证真实客人队列与画面。旧静态填充和单餐盒实验脚本已归档至本地 `archives/2026-11-03/demo2-author-experiments`，不作为当前生成入口。

审计：node --import ./tests/register.mjs tools/demo2-audit-shortcuts.mjs。

前1～5关保持本轮修改前数据。第6～11关的最终占用与食品数见 density-audit.json；最终关卡须使用真实actDrag及当前客人就绪队列验证，不能仅验证JSON可解析。

## 组合餐盒
第6/7关各1个双食物订单，第8关至少2个，第9～11关至少3个；包括L3+I1装O4、H2+H2装O4、I1+I1装H2。food按类型/形状/相对位置匹配，不按ID。tools/demo2-composite-recipes.mjs默认仅输出可行候选；--apply才替换数据。每个候选必须通过实际客户队列回放，拆分增加食品数但不改变格子并集占用率。

所有Node作者命令使用 `node --import ./tests/register.mjs 工具路径 [--apply]`。统一审计为 `tools/demo2-report-levels.mjs`；审计只更新JSON报告，不改Levels。工具之间引用的审计/队列函数不再触发CLI写入副作用。

## 当前验收限度
第9～11关并集占用72.5%/71.25%/72.92%，未达到曾尝试的75%目标，不伪称满盘。直接组装出餐方案数为2/0/1：第10关排除了无准备搬移的开局，其余仍允许少量顺手出餐；真实整关难度还需试玩，不用冗长的可行proof当作最优解或难度评分。

新极限组12～19为独立100%满盘借盒挑战；完整组合和必要性证据、单客窗口见EXTREME.md。旧9～11的稀疏指标仅描述常规组，不代表新挑战。
