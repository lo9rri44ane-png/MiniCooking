# 厨房解谜首版实现范围

日期：2026-10-30。状态：实现范围提案，未开始玩法编码。
依据：当前 GDD 与用户最新确认。目标引擎：package.json 中 creator.version = 3.8.8。

## 目标与方案
在现有 2D 框架内做出可直接 Creator 预览的厨房解谜试玩，同时支持编辑关卡、验证最优解和反复调整。
推荐沿用现有 UIService 页面路由，在 features 中添加独立玩法，不重建通用框架。相比每个页面新增场景，这种方式更少改变现有启动链；相比把玩法直接写进 Pages.ts，更容易复用同一规则做求解和编辑预览。
不另开引擎实例，不默认打包，不手写 scene、prefab 或 meta。新增元数据由当前编辑器导入生成。

## 当前规则基线
- 单厨师，上下左右滑行，遇边界或障碍才停；有效滑行一步，零位移不扣步。
- 经过材料自动拾取，基础模式不限材料顺序，背包容量可配置，示例为 7；每拾取一份材料后立即检查，占用达到容量即失败并停止后续滑行逻辑，不得先制作挽救。
- 棋盘材料总量恰好满足全部订单；订单展示材料类型和数量。
- 材料齐全且停在对应餐具前的操作格，自动制作；滑过操作格不触发。
- 制作播放动画并直接交付，消耗对应材料，动画不额外扣步；不再运输成品到客人交付点。
- 同一厨师继续完成全部订单，全部完成后表现为下班。
- 多厨师、按顺序收集保留为后续方案，不进入首版基础规则。

## 首版交付范围
### 游戏闭环
- 首页、选关、厨房关卡、暂停、失败／胜利结算、重试、下一关与返回。
- 上方三个客人展示位置，中部迷你厨房棋盘、可见餐具和操作格，下方可配置背包槽、剩余步数。
- 滑动为主要输入，桌面方向键辅助调试；输入到动画结束前锁定，防止重复移动和重复交付。
- 明确展示背包变化、材料需求、制作与订单完成；下班演出不附加移动目标。
- 步数耗尽、满包失败原因分别显示。失败提供免费重试，额外辅助功能单独决定。
- 通关记录、最少用步和顺序解锁下一关作为首版基础成长提案；奖励经济与装修尚未确认。

### 关卡编辑器
作为同一工程内的开发页面运行，第一版不做独立桌面工具。
- 配置棋盘尺寸、墙体、厨师起点、食材类型与位置、餐具类型及操作格、订单配方、背包容量和总步数。
- 支持画笔／擦除、草稿保存、JSON 导入导出、试玩、返回编辑；平台不支持文件下载时提供文本复制替代，不依赖 Node 文件系统。
- 展示每类材料供需差额、非法重叠、越界、缺失配方与操作格等错误。
- 修改玩法数据即令旧求解结果失效；解法绑定关卡内容版本和规则版本。

### 求解与算法辅助
- 使用与实际游戏相同的纯规则模拟，按有效滑行次数寻找最短解，并回放完整路径。
- 只有证明预算内不存在更短路径时才标记已证明最优；区别可行解、已证明无解及计算限额内未知。
- 搜索覆盖位置、材料剩余、背包计数、订单状态、剩余步数等实际规则；动画不进入逻辑状态。
- 设置搜索时间与状态数量上限，分批计算且可取消；编辑后丢弃过期结果，避免卡住编辑器。
- 算法辅助第一版提供基于已证明最短步数的步数预算建议，以及受约束的少量材料／障碍位置变更候选；候选重新验证后才展示，可预览、应用、撤回。
- 不承诺任意尺寸和材料数量都能快速求解。默认支持范围需通过基准关卡测试后确定；超限可存草稿，不能伪称已验证或发布为认证关卡。

### 首批验证内容（建议）
先做 6 个已证明可解的关卡：滑行教学、拾取教学、餐具停靠、背包绕路、两种配方顺序、三个订单综合。使用有名称和轮廓区分的占位图形，保留后续换美术接口。另备满包、最后一步制作、零位移、缺材料、滑过不制作等规则验证样例；未证最优不对外显示最优标签。

## 实施顺序与完成标准
1. 规则定稿：解决下方阻塞项，更新 GDD 当前规则摘要。
2. 纯规则与手工教学关：关键边界测试通过，同一初始状态和输入得到一致结果。
3. 接入 Creator：真实预览完成收集、停靠、制作、交付、胜败与重试；不是只做类型检查。
4. 编辑及求解：编辑后试玩一致、导出导入不丢参数；已知小棋盘验证最短解，超时不误报；回放用同一规则完成关卡。
5. 补齐 6 关与顺序解锁：重启后进度保留，重复结算不重复推进或发奖。
6. 视觉替换：另行讨论小动物厨师、卡通人类和迷你厨房方向，再确定正式美术范围。

每阶段保留必要验证记录。资源导入由编辑器完成；进行类型检查与既有框架回归，并在已有 Creator 预览中验证。当前不要求微信／抖音打包及真机发布验收。

## 编码前的规则阻塞项
1. 已确认：拾取后立即判满包失败，不是编码阻塞项。必须覆盖第 C 份材料、滑行途中满包、操作格上满包、配方需求份数达到容量等测试。
2. 已确认设备支持多菜谱，停靠后一次批量制作并交付所有材料足够且订单未完成的可制作食物，不逐道点选，不额外扣步。材料竞争时已确认按界面订单顺序优先制作，先消耗再检查后续订单；不支持或缺料的订单跳过。操作格布局仍需明确。
3. 已确认最多三位客人同时在场，全部需求完成后离开，后续按关卡预设顺序补位，整关可超过三位。已确认候场订单可查看但不提前制作；新客人补位后，设备与剩余材料满足时在同次停靠继续自动制作，直至无法制作或全部完成。

## 后续范围与未决项
多厨师、有序拾取、装修与奖励经济、正式美术、广告支付登录、正式平台发布均不混入首版试玩；其中用户已提出的扩展保留在设计记录，后续单独定稿，不视为删除。撤销、求解提示和加步是否属于玩家功能尚未决定；求解回放先提供给关卡开发者。
