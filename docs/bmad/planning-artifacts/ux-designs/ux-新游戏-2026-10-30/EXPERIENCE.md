# Foundation

目标玩家用单个厨师滑动收集材料，在有限步数内完成订单。玩家自主判断路线，界面负责明确剩余步数、背包风险、设备停靠与制作结果。正常试玩沿用现有160关数据；本轮不修改已确认玩法。

# Information Architecture

首页 → 餐厅 → 章节选关 → 玩法 → 胜利/失败 → 下一关/重试/选关。设置从首页进入，返回首页。玩法另有暂停、菜谱、教程、道具请求与GM调试弹层。

| 页面 | 主要行动 | 必须可获得的信息 |
|---|---|---|
| 首页 | 开始营业 / 继续 | 体力、总进度、最近未完成关 |
| 餐厅/选关 | 进入或查看锁定条件 | 店铺80关、章节、预算、最优步数、已通关 |
| 玩法 | 在棋盘滑动 | 三个活动客人、材料与工具、步数、容量、停靠位 |
| 胜利 | 下一关 | 实际步数、最优步数、辅助/GM标签、不扣体力 |
| 失败 | 重试 / 可用道具 / 返回 | 步数耗尽或背包满、已扣1体力、可恢复方式 |
| 暂停 | 继续开工 | 暂停不消耗步数；重试/离开按当前会话规则计费 |
| 设置 | 切换音乐/音效 | 当前开关值、本地保存、当前无默认音频素材 |

# Voice and Tone

短、具体、行动优先：“向右滑动”“停在料理台旁制作”“下班啦！”错误说明原因并给恢复路径，例如“广告未完成，格子尚未解锁”。禁止“成功”掩盖SDK缺失。首页统一使用“滑动教学”。

# Component Patterns

订单材料与棋盘同色同短名，数量独立标注。设备色块与名称配对。厨师保持呼吸与白边，位置只由规则层更新。背包初始7格，可配置；广告格始终在背包中，不是临时移走材料。

按钮仅在一次操作合法时执行；动画期间输入锁定，失败/胜利后不接受普通移动。广告请求期间禁止重复授奖；关闭页面后的迟到回调不可修改已退出局。

结算和暂停使用独立预制体并阻挡底层输入；菜谱是可关闭的独立面板；Toast只承载短反馈，详细错误用Popup。

# State Patterns

| 状态 | 反馈/布局 | 恢复与当前实现 |
|---|---|---|
| 启动加载 | 居中短文字，不显示虚假百分比 | 等待Creator资源导入；当前有启动文字，LoadingState为可复用视觉模板 |
| 启动失败/资源缺失 | 弹层显示具体错误 | 检查Creator导入与控制台；保留最小文本应急渲染 |
| 空客人槽 | 卡内“等待打烊”，不暗示还有任务 | 当前已实现；EmptyState另有通用模板 |
| 关卡锁定 | 灰卡+完成前关的说明 | 不进入、不扣体力，正常推进解锁 |
| 体力不足 | 短提示、体力恢复倒计时可见 | 不开局、不扣体力；等待每10分钟+1，GM可补充 |
| 移动无效 | 厨师不动、步数不变 | 可立即另向滑动；教程错误方向给行动句 |
| 动作中 | 禁止重复移动，教学暂隐 | 动画完成后刷新订单/背包/步数 |
| 背包临界 | 容量数字变警告色并保留“满即失败” | 不仅靠颜色表达；满格立即失败，不能等到烹饪时释放 |
| 停靠制作 | 播放制作/交付反馈，更新同停靠可完成的全部订单 | 只在停止于正确停靠点触发，路过不制作；按可见客人编号优先 |
| 广告请求/取消/缺SDK | 按钮请求中；失败弹层说明未解锁 | 只有完整观看成功才+1容量；当前真实广告尚未接入，GM仅调试 |
| 胜利 | “下班啦”、实际/最优步数、下一关 | 不扣体力；辅助/GM不伪装无道具最好成绩 |
| 步数耗尽/背包满 | 区分失败原因、已扣体力 | 每局失败或退出只扣一次；加班/撤回按已有使用限制恢复 |
| 存档异常 | 明确“原存档保留”，禁静默覆盖 | 修复/备份后再操作；设置可使用临时默认值 |
| 失焦/回前台 | 音频挂起/恢复，计时按真实经过时间 | 不重复扣体力，不重复交付 |

LoadingState/EmptyState/ErrorState是独立复用模板，不代表额外实现了联网加载、空餐厅数据或自动修复服务。当前项目以离线关卡、本地存档运行。

# Interaction Primitives

滑动决定上下左右，只移动选定的唯一厨师，直到障碍/边界才停。有效滑动记一步；零位移不记步。点击方向键和键盘为备用输入。停靠完成食物后直接交付，不再移动到出餐口。做菜不要求材料顺序；一份食谱可由同一设备支持，不同菜共享设备。

教程绑定真实动作事件：第1关右滑→上滑；错误动作不推进。新食材/设备/道具首次出现的关卡才触发相应教学。跳过不写入“教学完成”，下次仍可看到。教程不遮操作及结果，不用纯对白阻断。

# Accessibility Floor

色块+短名+数量同时存在；警告配文字。文字遵循 DESIGN.md 的 typography，避免在缩小标签中塞完整段落。最低触控目标以设备显示尺寸44px为目标，当前部分GM/跳过按钮仍需真机触控复核。滑动主输入同时有方向键；无必须听声音的任务。未来可加减弱动效开关，目前未实现，不标成已完成。颜色对比与读屏支持尚未做正式认证。

# HUD & Diegetic UI

订单最多并列三张，候场数量在其下方。棋盘上设备本体与旁边停靠位明确区分。背包位于棋盘下方，与道具按钮分区。完整配方点“菜谱”查看，不用在活动订单卡塞下所有客人的长清单。

# Input Schemes

移动端：棋盘滑动/按钮点按。桌面预览：鼠标拖动、方向键。模态开启时不透传输入；广告/自动路径中锁输入。当前仅验证Creator Web预览，微信/抖音真实SDK与真机适配另行验证。

# Game Feel & Juice

已有厨师1.8秒循环呼吸（缩放1到1.09）与光环脉冲；停止/销毁时释放Tween。已有动作演示、收集和制作反馈保留。正式美术建议收集粒子、锅具短动画、订单完成勾选、结算礼花，不把重特效覆盖路线；这些资源列为“待制作”，不作为本轮已实现。

# Responsive & Platform

720×1280设计基准，UIService根据SafeArea等比缩放；模态与Toast适配窄屏、方屏、横屏安全区域。保留刘海/系统手势安全边界。横屏不新增另一套布局。微信/抖音广告、登录、支付的不可用状态必须经平台适配器显式返回。

# Key Flows

## 小林首次完成营业
1. 小林从首页进入早餐店第1关，看到订单所需生菜、番茄与料理台。
2. 提示直接要求向右滑动；他滑动后厨师收集生菜，提示暂隐，结果可见。
3. 下一条要求向上滑动，收集番茄并停靠料理台。
4. 高潮：同一次停靠完成菜品并交付，出现“下班啦”，记录2步且不扣体力。
5. 失败分支：滑错方向不扣步、不推进教学，提示正确方向；跳过后恢复正常操作。

## 阿岚步数用尽后恢复
1. 阿岚在已开放加班的关卡耗尽步数，看到明确原因和已扣1体力。
2. 她点击本地试用加班，增加3步，结算层移除，棋盘继续。
3. 高潮：剩余步数内完成订单，成绩标记辅助，不覆盖无道具最好纪录。
4. 失败分支：加班已用则说明每局一次；重试或离开不重复扣同一局体力。

## 小周尝试广告格
1. 小周点击背包内“广告+1格”，请求期间不能重复点击授奖。
2. 预览没有接入SDK，弹出未解锁说明，背包材料与容量不变。
3. 高潮：将来平台返回完整观看成功时，原背包新增1个可用格；已有材料不移动。
4. 取消/失败/迟到回调均不授奖；GM测试扩展格明确标为调试。
