# 预制体与框架规范

适用工程：E:/Cy/小游戏demo 2/新游戏；Creator固定3.8.8。打开 assets/scene/main.scene，直接预览，不需要打包。

## 目录与职责

| 层 | 目录 | 职责 |
|---|---|---|
| 入口 | assets/scripts/app | 配置校验、服务生命周期、路由注册、启动异常 |
| 核心 | assets/scripts/framework/core | 事件、资源租约、异步路由、存档等纯逻辑，不引用cc |
| Cocos适配 | assets/scripts/framework/cocos | UIService、PrefabFactory、PrefabSlot、PrefabSurface、资源/音频 |
| 平台 | assets/scripts/framework/platform | 微信/抖音/预览能力；不可用显式返回，不假成功 |
| 玩法 | assets/scripts/features/kitchen | 规则、求解、会话、体力、进度、教程与界面控制 |
| UI资源 | assets/resources/prefabs | 45个原生预制体，页面/组件/弹层/状态/通用模板 |
| 配置 | assets/resources/config | 框架配置；关卡仍由CampaignData统一管理 |
| 编辑器工具 | assets/scripts/editor、tools/generate-prefabs.mjs | 原生序列化/导入工具，只在显式生成时调用 |
| 验证 | tests、tools/preview-prefabs.mjs、docs/verification | 规则测试、真实Creator预览、截图和报告 |

## 模块边界

- 页面：HomePage、RestaurantsPage、LevelSelectPage、KitchenPage、SettingsPage、DiagnosticsPage。
- 玩法：Board/HUD/Effects、Chef及主体/光环、地格/障碍/停靠位/设备、食材、订单、菜谱、背包、体力组件。
- 弹层：胜利/失败/暂停、菜谱、选择面板、系统弹窗/Toast、教程提示与目标。
- 模板：Container、Panel、TextLabel及加载/空/错误状态。容器为空是为了绑定运行时数据，不是某一关的静态截图。
- 规则、会话、求解、关卡、存档、平台SDK属于数据/逻辑，不做空预制体。

## 运行时绑定

Application在正常界面创建前通过CocosAssets预载预制体租约。PrefabFactory按页面名/组件名前缀选模板并使用instantiate；预制体缺失会进入明确启动错误。仅资源尚未可用的启动文字/应急错误界面允许最小节点回退。

PrefabSlot.bindingKey是序列化子节点的绑定键，不能随意删除或改名。页面控制器认领对应节点、更新动态文案并绑定回调；同帧未被认领的标记节点会移除，避免上一份关卡快照/旧按钮残留。新加入且不带PrefabSlot的美术装饰会保留。不要把可交互按钮当作未绑定的装饰加入，否则没有业务回调。

重复组件从各自预制体实例化；页面中的重复组件子树仅作为绑定占位，会替换为对应组件实例，因此应在通用组件预制体内修改其内部美术，不在页面副本内修改组件内部。页面中的位置/尺寸覆盖可由该占位根的preserveLayout保留；关卡行列、客人数量、材料、容量与列表分页仍由数据决定。UIService负责SafeArea、路由和系统弹层。KitchenPages是目前玩法的UI协调器；后续新系统新增独立控制器，避免把纯规则塞入界面组件。

## 编辑预制体的方法

1. 在Creator Assets中打开 assets/resources/prefabs 对应文件；修改后保存预制体。
2. 替换底图：在原绑定节点加Sprite并配置SpriteFrame，保留UITransform与绑定键。运行时识别有效SpriteFrame并隐藏同节点Graphics占位。
3. 修改字号/颜色：在对应节点的PrefabSlot勾选preserveStyle；修改Label/Graphics属性。默认关闭，原型仍按代码中的状态颜色/字号更新，避免食材颜色失配。
4. 修改静态布局：勾选preserveLayout后，编辑位置和UITransform尺寸。棋盘格、材料、厨师、订单列表等数据驱动节点不应启用；它们必须跟随关卡尺寸。
5. 装饰节点不加PrefabSlot；其美术可以自由布局。数量、名字、步数、倒计时、订单文本仍由逻辑更新。
6. 在现有main.scene预览检查。不要直接编辑prefab JSON或meta，不要删除绑定组件后用名字碰运气。

Graphics的绘制路径不存入预制体。PrefabSurface负责编辑器占位展示；运行时绑定图形由UI控制层重画，避免教程描边被重建为实心遮罩。Sprite素材不经过色块绘制。动画仍由控制器驱动、销毁时停止，预制体负责可编辑的展示结构。

## 生命周期约束

页面销毁：解除输入/事件、清除定时器、停止Tween、终止教程/自动路径；资源租约由Application统一释放。广告回调在会话已退出时忽略。异步路由只接受最新请求。失败或退出体力每局只扣一次。GM演示不写普通最佳成绩。

主场景保持Canvas/UICamera，Canvas挂MinigameApplication；没有额外示例节点或残留导出器。编辑器内部前景/背景不是游戏节点，不删除。

## 重新生成与验证

日常改美术只保存预制体，**不要重新运行生成脚本**。tools/generate-prefabs.mjs是从占位蓝图重建资源的开发维护工具，会覆盖预制体编辑内容；仅在明确要重建基线时运行。工具先检查目标项目，在main.scene临时挂原生作者组件，以EditorExtends.serialize+asset-db生成，完成删除临时节点并保存干净场景。

检查命令：npm test；npm run typecheck；node tools/preview-prefabs.mjs；node tools/preview-tutorial-action.mjs。后两条需要当前Creator预览服务7456。测试只证明当前桌面Web预览与规则，不代表微信/抖音广告或真机已验收。
